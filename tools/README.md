# tools/ — 启动期与主题的真实运行观测

这些脚本是「窗口生命周期 / 主题闪烁」这类问题的验收手段。它们存在的理由：
这类缺陷**在浏览器里预览完全看不出来**——浏览器没有原生窗口、没有 WebView2 的
初始化脚本时序、没有真实的系统主题。必须在真实 exe 上观测。

## 为什么不能只看代码或浏览器

2026-09-26 那轮「双击 exe 闪烁」的排查结论（都由这些脚本给出，不是推理）：

- 初始化脚本 `document.documentElement.dataset.theme = '...'` 在 WebView2 里
  抛 `TypeError`——脚本执行时 `documentElement` 还是 `null`，属性永远落不上。
  页面于是先用浅色画出来，约 0.9 秒后才被设置接口补上，整页可见地翻一次主题。
- 翻转的 0.9 秒延迟来自 `app_settings`：它每次都 spawn ffmpeg 做版本探测
  （实测 811ms），而前端要等它返回才知道主题。
- 原生窗口底色只在 `system` 模式设置，显式浅/深色时窗口是一块 WebView2 的白色。

## 脚本

前置：应用需要带调试端口启动。

```bash
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222" ./target/release/bilidown.exe
```

| 脚本 | 回答的问题 |
| --- | --- |
| `trace-window.ps1` | 启动瞬间（15ms 采样）创建了几个顶层窗口、何时由隐藏变可见、尺寸/位置怎么变。用于判定"是否出现了第二个实例的窗口"。 |
| `cdp-probe.mjs` | 启动全程的 DOM 时间线 + 控制台异常 + 逐帧截图。用于看首帧配色、有没有未捕获异常。自开进程，启动应用前先跑它。 |
| `cdp-visibility.mjs` | **最有用**：在文档创建前注入探针，把「`data-theme` 何时写入」「首帧背景色」「窗口何时可见」「DOM 何时填充」记在**同一条时钟**上，然后 reload 复现一次干净加载。用于判定"先绘制还是先显示""首帧是什么颜色"。 |
| `cdp-toggle.mjs` | 真实点击右上角主题按钮，录下主题变化与 toast 文本。用于区分"主题切换本身有问题"和"启动期的问题"。 |
| `watch-window-events.ps1` | **事件驱动，不漏毫秒级闪现**：`SetWinEventHook` 监听全系统顶层窗口的 CREATE/SHOW/HIDE/DESTROY/FOREGROUND。15ms 轮询抓不到的东西（一闪而过的窗口）全靠它。 |
| `capture-startup.ps1` | 用 `PrintWindow(PW_RENDERFULLCONTENT)` 逐帧抓应用窗口，看用户实际看到的画面。 |

## 2026-09-26 第二轮：真正"弹"的是一个终端窗口

用 `watch-window-events.ps1` 抓到的（轮询、逐帧截图、DOM 探针都漏了这个）：

```
1539 SHOW    cls=CASCADIA_HOSTING_WINDOW_CLASS title='Windows Terminal'
1651 HIDE    ... title='C:\Users\87845\AppData\Local\Programs\ffmpeg\bin\ffmpeg.exe'
1914 SHOW    ... （第二次）
```

程序是 GUI 子系统（`windows_subsystem = "windows"`），但 spawn 控制台程序
（`ffmpeg -version`）时不抑制控制台，Windows 就会为它新建一个终端窗口——
**每次 spawn 弹一个终端一闪而过**；合成视频时终端会一直挂着。
修法：`creation_flags(CREATE_NO_WINDOW)`；另外 `path_ffmpeg` 改为纯 PATH 文件系统
查找，去掉了一次纯粹为了"试试能不能跑"的多余 spawn（探测 811ms → 68ms）。

**教训**：GUI 程序 spawn 控制台子进程必须 `CREATE_NO_WINDOW`。这类缺陷在
DOM 层、窗口几何层、应用窗口截图层全都不可见——子进程的窗口属于另一个进程。

`cdp-visibility.mjs` 依赖 `Page.addScriptToEvaluateOnNewDocument` + reload：
**初始化脚本在首次加载与 reload 时行为一致**，所以 reload 可以复现真实加载。
注意它烘焙的是**进程启动时**读到的主题（初始化脚本在 Rust 侧一次性生成），
所以换主题后再测，必须重启进程。

## 踩过的坑

- **不要用 GDI 截屏（`Graphics.CopyFromScreen`）采 WebView2 的颜色**：
  WebView2 走 GPU 合成，GDI 抓到的是纯黑，会得出"窗口是黑的"这种错误结论。
  要看画面就用 `Page.captureScreenshot`。
- **跨进程时钟对不上**：PowerShell 启动 + `Add-Type` 编译比 Node 慢几百毫秒，
  两个脚本各自的 `t=0` 不是同一时刻，跨脚本比较时间线会得出相反结论。
  要么把观测放进同一个进程，要么让页面自己采集（`cdp-visibility.mjs` 的做法）。
- **`.ps1` 里的中文**：无 BOM 时 Windows PowerShell 按 ANSI 解码，中文注释会
  破坏语法。本目录的 `.ps1` 一律保持 ASCII。
- **`Runtime.enable` 会重放页面生命周期内最后那次未捕获异常**，别误当成"刚发生"。

## 列表里的文件名预览

选择页的表格多了「文件名」列，单视频则在详情里显示一行（如 `今日份缇宝/P1 - 今日份缇宝.mp4`）。
名字由后端 `preview_names` 用**和真正落盘同一个渲染器**算出，所以列表里看到什么，
下载出来就是什么；命名模板一改（保存后回到解析页），这一列立刻跟着变。

变量取值由前端按来源类型算好（与提交下载时是同一套 batchNaming / singleNaming），
所以"番剧没有分P"这类情况会如实反映出来——比如番剧套用「分P视频」模板会渲染成
`…/P - .mp4`，这是预览在提醒模板不适用，不是算错。

`test-persist.mjs` 覆盖列顺序与对齐；`probe-naming.mjs` 覆盖命名预设与模板的联动。

## 单视频页的弹层位置

`spacer` 原来放在 `v-if="activeIsBatch"` 里，单视频时没有它，动作按钮靠左，
于是右对齐展开的「下载设置」弹层会往左跑出按钮、盖住详情块。现在 spacer 无条件保留，
动作永远靠右，弹层向左展开就落在卡片内（实测弹层 [694,980] ⊂ 卡片 [218,1079]）。
弹层宽度也用 min(286px, calc(100vw - 60px)) 夹住，窄窗口下不会溢出。

## 多个单视频 = 一个清单

贴多行视频链接解析后，不再是一个个切标签看详情，而是像批量来源那样以列表呈现
（序号 / 标题 / UP 主 / 时长 + 勾选 + 已选统计 + 下载所选）。清晰度/音轨用一个共享
档位（取第一个视频的推荐值），下载时逐个按各自来源入队；命名仍走 singleNaming，
所以每条的名字各自算自己的 P1 标题。

只有 1 个视频时仍是详情块（封面 + 元信息 + 文件名）。单视频的文件名一行放不下会
折成两排（`-webkit-line-clamp: 2`），超过两排才省略。

`test-multi-video.mjs` 覆盖：多视频出表格不出详情、表头与行内容、勾选计数联动。

## 视频链接在两种模式下的不同行为

`probe_source` 有个 `preferCollection` 开关：批量解析模式传 true，单个视频模式传 false。

- 批量解析 + 视频链接：先查该视频的 `ugc_season`（所属合集），有就把整个合集拉出来
  （kind=collection，可继续分页），并注明「该视频属于合集「X」，已按合集解析」；
  视频不在合集里则退回解析这一个视频
- 单个视频 + 视频链接：始终只解析这一个

`test-collection-expand.mjs` 覆盖同一链接在两种模式下分别得到「合集 + 表格 35 行」
与「视频 + 详情块」。

## 一切来源都用同一张列表

现在只有一种呈现：**所有来源摊成同一张表**。

- 单视频 = 表里的一行（不再有封面详情块）
- 多个单视频、合集 + 单视频混合 = 同一张表里的多行，按来源顺序拼接
- 因此来源切换标签也去掉了（列表已经全摊开，切换是死控件）
- 表头：单一来源显示它的标题与类型；多来源显示「N 个来源」（全是单视频时显示「N 个单视频」）
- 行序号 `seq` 是它在表里的位置；命名模板用的 `index` 是它在**自己来源里**的位置
  （单视频固定 0，渲染成空）——所以加一个视频不会改变合集里各条的 `{index}`
- 行悬停显示该行将落盘的文件名（后端同一渲染器算出）

`test-unified-list.mjs` 覆盖三种情况：单个视频 1 行、多来源 101 行、混合 101 行，
都不出现详情块与来源标签，且行悬停带文件名。

## 多来源在表里的区分

多个来源摊进同一张表时，每个来源前面加一条**分组行**：类型标签 + 来源标题 + 条数
（如「[合集] 合集·星穹铁道 100 条」），用浅色底与上下边框把各组分开。
只有一个来源时不画分组行——表头已经写了它是谁。序号跨组连续，所以整个清单仍然是一张表。

`test-unified-list.mjs` / 手工验证：单来源分组行 0 条；两来源分组行 2 条、数据行 101 条、
序号从 01 开始。

## 分组可折叠

点分组行收起/展开该来源的行，分组行左侧的三角跟着转。收起后分组行仍显示
「类型 + 来源名 + 条数」，底部统计与勾选不受影响（折叠只是不显示，行还在，全选仍然覆盖它们）。

`test-fold.mjs` 覆盖：初始 101 行可见、折叠第二个来源后可见 1 行且该组带上 folded 类、
底部仍是「共 101 项」、折叠状态下全选得到「已选 101 项」、再点一次恢复 101 行。

## 分组选择框

每个分组行左侧有一个选择框，只勾选该分组内的条目（不影响别的来源），与行内勾选框左对齐。
部分勾选时显示半选横杠。点它不会连带折叠分组（`@click.stop`）。

`test-group-check.mjs` 覆盖：勾第一组得 1 项、再勾第二组得 101 项、取消第一组得 100 项、
取消组内一行后该组变半选且总计 99 项，全程折叠状态不变。

## 解析去重

三层去重，避免同一内容被解析两遍、下载两遍：

1. **输入行**：同一链接贴两次只解析一次（`lines()` 去重）
2. **来源**：后端给每个来源一个身份 `key`（`video:BV..` / `collection:{mid}:{sid}` /
   `space:{mid}` / `fav:{fid}` / `bangumi:{sid}` / `cheese:{sid}`）。视频链接在批量模式下
   展开成合集时，key 记的是**合集**身份，所以「同一合集里的两个视频」会被识别成重复来源，
   直接跳过（连请求都省了）
3. **内容行**：同一 bvid/ep 只出现一次，覆盖「合集与其中单个视频」「UP 空间与它的一条投稿」
   这类部分重叠；被覆盖完的来源不再显示分组行

底部会显示「（已去重 N 条）」，跳过来源时弹提示。

`test-dedupe.mjs` 覆盖：同合集两个视频、同链接两次、合集 + 其中视频、合集 + UP 空间 + 空间里的视频。

### 去重明细展示

跳过的重复来源会**列在「解析结果」卡片里**（不是只弹提示）：每条给出输入链接与原因
（「与前面的链接相同」/「与「合集·木鱼说」是同一个来源」）；内容级合并的条数也会附一行。
提示条只说"已跳过 N 个重复来源，明细见解析结果"。清空解析结果时明细一起清掉。

明细列表有高度上限（108px，约 4 行）并**在框内滚动**，条目多时也不会把整页撑长；
超过 5 条时头部会写「（列表内可滚动）」。

## 解析页的尺寸自适应

宽度始终占满（不限宽）。**竖向**自适应：`.parse-page:not(.fill-height)` 是 flex 列 +
`min-height: 100%`，两张卡 `flex: 1 1 auto` 分摊窗口高度——解析链接卡里的输入框、
解析结果卡里的去重明细都会吃掉各自卡内剩余高度，所以窗口拉高时底部不再留一片空白。

窗口不够高时（内容本身需要的高度超过窗口）页面照常滚动，这是必然的。

**明细列表要在卡内滚动，关键是卡片高度必须有确定值**：结果卡用 `flex: 2 1 0`
（basis 0 → 高度只由分配决定，不被列表内容撑高），卡内的明细框再 `flex: 1` 吃掉
剩余高度，列表才有确定高度可滚。踩过的坑：
- 只给列表 `max-height: none` + `flex: 1`，卡会跟着列表内容长高 → "列表内滚动失效"
- 结果卡的 `min-height` 要**装得下卡内固定部分 + 明细框的最小需要量**：
  内边距 40 + 标题行 38 + 预设行 38 + 明细框（外边距 12 + 内边距 20 + 小标题 24 + 列表下限 80）
  ≈ 252，取 260。取值太小（160）时明细框比卡片还高，列表底部会被卡片边缘切掉
  —— 这是另一种形态的"内容溢出卡片"
- 明细列表 `min-height: 80px` 保证至少露出 3 行（每行 26px），不够就在框内滚
- 输入卡的 `min-height` 必须小于 `max-height`，否则 min 优先、上限失效（实测卡在 503 不动）
- **不要用 `max-height` 压输入卡**：上限小于内容的最小高度时，被压的是卡片盒子而不是
  内容，内容会溢出卡片、被下面的卡片盖住（表现是"解析结果卡盖在解析链接卡上"）。
  正解是让输入卡 `flex: 0 1 auto`（按内容、不拉伸），把多余高度全给结果卡
- 输入框给确定高度（`height: 110px` + `min-height` 同值），否则 rows 的固有高度会把
  输入卡撑高

`test-responsive.mjs` 改窗口尺寸后断言：高窗口（1400x1300）下最后一张卡的底边 =
内容区底边 - 内边距、整页不可滚；矮窗口下可滚。

改窗口尺寸用 `tools/resize-window.ps1`（外部改，不依赖应用自己的窗口 API）。
该脚本踩过两个坑，注释里写明了：**不要用 MainWindowHandle**（进程里还有 Tao 的消息窗口，
可能改到它上面，表现为"改了尺寸界面不动"）；窗口最小化时位于 -32000,-32000，要先还原。
